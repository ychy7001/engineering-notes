# 发布与同步

## 一份正文，多处发布

文章源文件放在 `articles/<slug>/index.md`，图片和可公开数据放在同目录。优先修改源文件，再同步平台文章。GitHub 已公开不等于其他平台已经发布；各平台链接应在发布验证完成后再添加。

首篇文章建议：

- 标题：API 首字等待几十秒，后台却只统计 6 秒：一次公网入口延迟排查
- 分类：后端 / 运维相关分类，以平台实际可选项为准
- 标签候选：网络、后端，发布前核对平台实际标签
- 摘要：一次编程助手 API 请求延迟排查：通过本机与公网对照、正文接收计时和多来源实验，把模型耗时与入口延迟分开，最终保留橙云代理，替换 Tunnel 回源路径，并记录效果及尚未查明的问题。

平台发布时上传 `before.png`、`after.png` 到平台图片服务，替换正文中的相对路径。CSV链接改为GitHub上的公开结果文件链接。不要假设任意平台支持仓库相对链接或能稳定加载GitHub图片外链。

## 掘金候选的接入方式

推荐由作者在自己的浏览器完成掘金登录。选定工具并检查实现后，先做账号身份核对和单篇草稿验证，再处理正式发布。文章写作、数据校验、配图和平台格式转换可以交给助手；短信验证码或扫码登录仍由作者完成。

工具和登录数据应放在内容仓库之外的私有工作目录。不要在聊天中粘贴 Cookie、将浏览器会话文件提交到仓库，或对公网开放浏览器调试端口。当前仓库没有安装任何发布插件，也没有包含登录凭证。

如果接入第三方发布器，还需核验正文图片上传、相对链接转换、草稿重复创建与发布结果确认。CLI存在不等于这些环节已经可用；本轮未向掘金创建草稿或发布文章。

`web-publish`的实际CLI参数比简写示例多：建稿还必填`--title`、`--brief`、`--tag-ids`、`--category`。已经验证的是离线命令和代码分支，不是账号认证、真实建稿或审核通过。

源码直接读取Markdown全文，没有实现正文相对图片的上传和替换，也没有为每篇本地文章持久保存跨平台文章ID。更新依赖查找最近的文章列表。接入时仍需补齐图片处理及本地文章与远端ID的对应关系。

[DEV Community / Forem 官方API](https://developers.forem.com/api/v1)是另一种选择：支持Markdown文章、`published`草稿状态、更新文章和`canonical_url`，使用API Key认证。若以官方接口稳定性为首要标准，可优先选择；是否符合中文内容受众则由作者决定。未核实的Hashnode订阅变动、博客园当前账号API权限，不作为本次选型结论。

2026-10-19 直接读取博客园官方团队博客的 [RSD 描述文件](https://www.cnblogs.com/cmt/rsd.xml)，返回的 engineName 为 CNBlogs，API 名为 MetaWeblog，preferred 为 true，apiLink 指向 `https://rpc.cnblogs.com/metaweblog/cmt`。这是官方站点提供的协议发现信息；该地址属于官方团队博客，不能当成作者自己的写入地址。

这一证据确认官方协议入口存在，但没有验证新账号开通条件、认证凭据、草稿写入、Markdown 格式及图片上传。作者开通自己的博客后，应从该博客的 RSD 获取入口并逐项实测，再决定是否需要自编轻量 CLI。没有将其他平台的 API Key 用于博客园，也没有创建第三方平台文章。
